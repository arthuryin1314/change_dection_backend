# 4b：自动补算编排、状态查询与失败重试

## Parent

https://github.com/arthuryin1314/change_dection_backend/issues/6

## What to build

用户选择两期影像和一个模型后直接发起检测任务，无需先手动识别。系统自动补齐缺失的分类结果并保存，复用符合版本和权限的结果；只有前后两期的完整识别结果均已成功保存、可读取后，才进入两期比较并执行既有矩阵计算。

## Acceptance criteria

- [ ] 两期都缺失、仅一期缺失、两期均有匹配结果均可自动完成，去除要求先手动识别的阶段性限制。
- [ ] 复用条件区分用户权限、影像版本、权重版本和影响推理的配置；两期使用同一模型版本，资源更新不得误用旧结果。
- [ ] 页面展示任务处理中及失败状态，任务可查询；用户无需保持单个长时间 HTTP 请求才能获得完成结果。
- [ ] 任一期失败不得生成成功矩阵，半成品不能参与复用，成功识别结果可在后续检测中复用。
- [ ] 本任务在任务 2（#9） 建立的统一错误码清单中追加识别执行失败码，明确失败时期、任务失败状态与可重试语义；不得将执行失败混同“尚无识别结果”，也不得另建或重定义错误码体系。状态查询、前端反馈和重试测试使用同一契约。
- [ ] 补算流程调用共享识别能力和矩阵能力，沿用现有执行设施，不强制引入独立队列服务。
- [ ] 显式调用任务 1a（#7） 可程序化识别与保存流程；仅在两期完整就绪后进入矩阵计算。缺失检测使用任务 2（#9） 的 IDENTIFICATION_RESULT_UNAVAILABLE 及逐期原因；版本查找与复用不再由独立任务 4a（#10） 实现。
- [ ] 冻结任务所用影像、权重和分析参数版本；运行中资源更新不得使前后两期混用版本。
- [ ] 同用户同版本及参数的重复请求不得启动重复的在途补算；请求返回已有在途任务或复用其结果，必须以并发测试证明，而非仅禁用按钮。
- [ ] 失败后可由用户重试，返回可追踪的新尝试；复用已经完整成功的单期结果，只补算缺失或失败部分，不沿用失败的成功状态。
- [ ] 刷新后仍可查询在途任务。后台执行异常或重启不得永久留在假处理中，应能报告失败并允许重试；不要求引入自动无限重试。
- [ ] API 验证三种命中情况、版本变化、识别失败和越权；替代模型推理但保留保存与矩阵计算，前端测试验证状态和失败信息。
- [ ] 完成项目必需检查，可演示未事先识别的两期影像一键得到矩阵。

## Blocked by
