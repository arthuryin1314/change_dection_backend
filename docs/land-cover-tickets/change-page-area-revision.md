## 已确认产品变更

- 地物识别页保持识别与色块展示，不新增六类面积面板。
- 变化检测页设“变化前”“变化后”两个区域，各自选择影像，自动关联已有识别结果，显示该结果的六类面积；用户不直接挑选结果记录。
- 两侧面积分别代表各自整幅影像的有效区域；矩阵面积只覆盖共同有效区域，明确标注两种范围，不要求单期面积等于矩阵行列合计。
- 平方米存储、默认公顷、六类 0–5、NoData 独立及切换单位不推理等约束不变。

## 架构与所有权建议

- 沿用此前确认的一个识别模型供两期共用，不按 image_id 取最新历史结果。模型选择器的具体位置不固定。
- #8 交付按完整身份解析已有结果的只读查询入口：用户权限、影像内容版本、权重内容版本、规范化推理参数、分类体系版本全部参与匹配。先复用 #7 已有 get_by_identity 能力，缺少的是对外只读入口及页面接入，不重做身份机制。
- 现有创建识别结果接口可能触发推理，不能作为选择影像时的查询入口。只读查询未命中返回明确未就绪状态，不推理、不创建分类结果。
- 分类结果命中但面积汇总尚缺失时，#8 可通过单独的统计请求从持久化栅格计算并保存平方米；只读解析自身不承担写入，任何分支均不重跑模型。
- #9 复用 #8 的查询入口、前后选择状态、页面区域及单位转换；保留检测时重新校验版本与完整性以及统一矩阵错误码职责，不再另写身份查找模块。
- #11 负责查询未命中后的自动识别、保存、重试和任务状态，接入已有前后区域状态；#8 不提前实现这些能力。
- #8 的只读查询状态应可复用并能被 #9 映射为 IDENTIFICATION_RESULT_UNAVAILABLE 等统一错误；区分未匹配与权限错误，不为未匹配情况泄露其他用户数据。

## issue8 只读调查补充的接口约束

以下代码事实由 issue8 对话只读调查转达，实施前结合最新代码复核；接口名称及模块拆分为实现建议。

- 已有 SqlAlchemyClaimStore.get_by_identity(user_id, identity_sha256) 为纯查询，但只返回精简结果记录。命中后需要读取详情与验证文件完整性，不能调用会认领／创建结果的流程。
- 现有 _resolve_source_hashes 会更新 ORM 字段并 flush，已有详情 GET 的文件损坏分支会 invalidate 并 commit；新的只读解析不能直接复用这些带写入副作用的完整路径。
- 可复用只读内容哈希计算、ResultIdentity.sha256 及文件验证基础能力；身份还须包含 pipeline_version 和 grid_policy_version。哈希缓存未命中时在内存计算，不能回退为只按 image_id 查最新结果。
- 建议新增静态 resolve 查询入口，路由在动态结果 ID 路由前注册；区分匹配、缺失、处理中、失败、不可用。只有完整匹配才返回可用结果与面积状态。具体状态命名由实现确定，#9 将其映射至矩阵错误契约。
- 已匹配分类缺少面积时单独提交该 result_id 的面积统计；写入幂等、遵循用户权限，统计失败不使有效分类失效。解析自身不触发统计写入。
- 前端用共用模型和前后独立请求序号，保存返回的 resultId、identitySha256 与原始平方米。渲染和面积固定到同一结果身份；模型切换使两侧失效，迟到响应不得覆盖新选择。
- 测试明确覆盖：只读解析在哈希更新、文件损坏、处理中或未命中时均不写库、不认领、不推理；面积统计与只读查询的副作用边界分别验证。
