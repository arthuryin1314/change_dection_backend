# 2：两期识别结果齐备后计算、展示并保存转移矩阵

## Parent

https://github.com/arthuryin1314/change_dection_backend/issues/6

## What to build

用户在变化检测页面选择前后两期影像与模型。只有两期均已完成地物识别，并且各自的完整空间分类结果已成功保存、可读取时，才进入两期结果比较，计算、展示并保存 6×6 地物类型转移面积矩阵。矩阵依据两期逐像素分类及空间位置计算，不依赖单期面积汇总或面积列表先完成。

本任务先覆盖两期结果采用同坐标系、同像素网格的情况，允许影像覆盖范围不同但网格对齐；不同网格由任务 3（#13） 扩展，缺失识别结果的自动补齐由任务 4b（#11） 扩展。

## Acceptance criteria

- [ ] 页面可选择前后期影像及模型，执行检测并显示计算中、成功和失败状态；任务状态及结果可查询。
- [ ] 页面从本任务开始明确提示输入影像须已配准，同网格不代表已完成内容配准；系统不自动纠正位置偏移，此提示不等任务 3（#13） 才提供。
- [ ] 后端只调用任务 1a（#7） 的共享像元地表面积能力累加矩阵，沿用其平方米和数值容差口径，不自行实现经纬度或投影面积算法。
- [ ] 本任务复用 #8 的完整身份只读解析能力，不重复实现版本查找；检测前重新验证当前用户、影像和模型版本及结果完整性。两期匹配完整结果时不调用推理，直接比较。原 #10 的复用验收由 #8 查询与本任务矩阵集成共同覆盖。
- [ ] 本任务建立统一错误码清单及错误响应契约，集中定义 GRID_MISMATCH、NO_COMMON_VALID_AREA、IDENTIFICATION_RESULT_UNAVAILABLE。后续任务在同一清单追加新码，不重定义已有含义；任务 4b（#11） 负责追加识别执行失败码及其逐期信息、任务状态和重试语义。
- [ ] 缺失或版本不匹配返回 422、稳定错误码 IDENTIFICATION_RESULT_UNAVAILABLE，并分别标明前／后期及 MISSING、VERSION_MISMATCH、INCOMPLETE 原因，供任务 4b（#11） 判断补算；未授权资源按现有权限错误处理，不泄露其他用户结果。
- [ ] 验证双命中、单缺失、双缺失、参数／内容版本变更和不完整文件；相同条件再次检测不触发推理。不得只按模型 ID 命中旧权重结果。
- [ ] 开始矩阵计算前，确认前期和后期各自的完整识别结果均已成功保存、可读取，且匹配所选模型版本；任一期未完成、失败或仅有面积汇总时不得开始矩阵计算。
- [ ] 行为前期、列为后期，按固定六类顺序显示全部 36 格。复用 #8 的页面骨架、前后选择状态和单位转换，默认公顷并支持平方米、平方公里，不另建选择状态或换算实现。
- [ ] 公共有效区定义固定为：空间覆盖交集内，前期有效掩膜 AND 后期有效掩膜为真的像素；即排除任一期 NoData 的并集，不是保留 NoData 的交集。任务 3（#13） 沿用该定义。
- [ ] 对角线为未变面积，总和为公共有效面积。统一错误契约：交集为空返回 422 和稳定错误码 NO_COMMON_VALID_AREA；任务如已创建则标记失败，前端明确提示且不展示成功矩阵。
- [ ] 保存两期结果引用、影像及模型版本快照、矩阵、范围、网格、共同有效面积和时间；成功后可以通过详情接口重新读取。
- [ ] 持久化采用平方米且保留精度；接口只有在结果完整保存后才能报告成功，为任务 5（#12） 提供真实可读的历史数据来源。
- [ ] 网格不一致必须返回 422 和稳定错误码 GRID_MISMATCH，不得生成或保存成功矩阵；检查坐标系、像素大小、方向／旋转及网格原点对齐，而非仅比较宽高或分辨率。覆盖范围可不同。
- [ ] 此阶段缺失匹配识别结果或网格不兼容时给出明确提示，不生成错误成功结果；这些阶段性限制分别由任务 4b（#11） 和任务 3（#13） 移除。
- [ ] 无共同有效区域明确提示；身份和资源权限沿用现有约定。
- [ ] API 测试使用已知掩膜验证全部矩阵元素、方向、总面积、部分重叠、失败和持久化读取；覆盖前期缺失、后期缺失及识别未完成时不进入矩阵计算，前端会话测试覆盖提交参数与结果状态。
- [ ] 完成项目必需检查，可在页面演示两期已识别影像得到矩阵。
- [ ] 用真实尺寸的两期结果验证交叉表计算耗时和峰值内存，记录数据规模和机器；避免为 36 格交叉表构造不必要的整图中间数组。若需分块，验证分块交叉表与小样本完整计算一致。

## Implementation sequence

本 Issue 内部分两步交付，不再拆 Issue，可采用两个连续 PR：

1. 先打通两期已存在完整结果 → 同网格矩阵 → 持久化 → 页面展示的闭环，保留基本版本一致性、权限、网格及有效区检查，不让阶段性代码生成错误矩阵。
2. 再补齐按完整版本身份查找、缺失原因和统一错误码各分支及相关测试。整个 Issue 仅在全部验收完成后关闭，不能第一步合入就标记完成。
