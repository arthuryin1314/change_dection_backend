# 地物分类面积统计、两期转移矩阵与历史记录

## Problem Statement

用户目前可以在地物识别页面查看分类色块和图例，但无法查看每类地物的面积，也无法保存可用于后续计算的空间分类结果。变化检测页面尚未实现，用户无法选择两期影像，了解林地转为建筑等地物类型转换的面积，或重新查看历史计算结果。

## Solution

地物识别页面保持识别与分类色块展示，不新增六类面积面板。变化检测页面分为“变化前”和“变化后”两个区域，两侧各自选择影像，在两期共用的所选模型下自动关联匹配的已有识别结果，展示各自整幅有效区域的六类面积；用户不直接选择识别结果记录。

用户在变化检测页面选择前期影像、后期影像和一个识别模型。系统复用匹配版本的识别结果，自动补算和保存缺失结果，再统一空间网格，在两期共同有效区域内生成 6×6 地物类型转移面积矩阵。矩阵行表示前期类别，列表示后期类别，对角线表示类别未变的面积。

识别结果和变化结果持久化保存，变化检测页面提供历史入口。面积按平方米保存，默认以公顷展示，支持切换平方米和平方公里。首版要求输入影像已经配准，系统不纠正影像内容的位置偏移。

## User Stories

1. 作为系统用户，我希望识别后仍能看到分类色块和对应图例，以便定位不同地物。
2. 作为系统用户，我希望看到每类地物的面积，以便量化单期地物分布。
3. 作为系统用户，我希望单期统计覆盖整幅影像的有效区域，以便统计不随地图视口变化。
4. 作为系统用户，我希望隐藏图例或修改透明度不改变面积，以便自由查看地图。
5. 作为系统用户，我希望识别结果自动保存，以便后续变化分析复用。
6. 作为系统用户，我希望明确选择前后两个时期的影像，以便确定变化方向。
7. 作为系统用户，我希望选择一个识别模型用于两期分析，以便使用一致的分类定义。
8. 作为系统用户，我希望缺失识别结果时系统自动补算，以便无需切换页面手动识别。
9. 作为系统用户，我希望已有匹配结果被复用，以便减少等待。
10. 作为系统用户，我希望影像或模型权重更新后不误用旧结果，以便结果对应本次选择。
11. 作为系统用户，我希望不同覆盖范围的影像也能比较，以便分析共同区域。
12. 作为系统用户，我希望缺失数据不被当作地物变化，以便避免虚假的转移面积。
13. 作为系统用户，我希望查看完整六行六列矩阵，以便了解所有地物类型之间的转换。
14. 作为系统用户，我希望清楚看到行列的时期和类别名称，以便正确理解转移方向。
15. 作为系统用户，我希望对角线体现类别未变的面积，以便区分保留与转化。
16. 作为系统用户，我希望默认使用公顷并可切换单位，以便适应不同面积尺度。
17. 作为系统用户，我希望计算中和失败时有明确状态，以便知道任务是否完成。
18. 作为系统用户，我希望无共同有效区域时得到明确提示，以便更换影像。
19. 作为系统用户，我希望变化矩阵和计算上下文一起保存，以便复查。
20. 作为系统用户，我希望刷新或重新进入后能从历史打开结果，以便无需重新计算。
21. 作为系统用户，我希望历史显示计算时的影像和模型版本，以便辨别不同结果。
22. 作为系统用户，我希望只能访问自己有权限的结果，以便与现有资源权限一致。

## Implementation Decisions

### 分类与面积口径

- 六类沿用当前模型编号：0 其他／背景、1 水系、2 林地、3 道路、4 种植土地、5 房屋建筑。图例、面积列表及矩阵共享一致的类别定义；色块与图例颜色必须对应。
- 原始类别栅格是统计依据；保存空间参考、实际推理网格、有效数据掩膜及六类面积，不从渲染或缩放后的彩色图片反推分类。
- 单期统计整幅有效区域；矩阵只统计两期共同有效区域。NoData 和未覆盖区域排除，有效背景类保留。
- 后端以平方米保存未作展示舍入的面积。经纬度数据采用正确的地表面积换算，不能将经纬度差直接当作米制长度，也不能把显示地图的面积直接当作地表面积。
- 面积显示默认公顷，换算关系为 1 公顷 = 10,000 平方米、1 平方公里 = 1,000,000 平方米。舍入仅在展示层进行。

### 空间计算

- 输入影像须已完成位置配准。系统统一坐标系、像素大小和网格，分类使用最近邻重采样，有效掩膜同步处理。
- 分析网格策略必须确定且可追溯，记录在结果中。建议不采用比两期较粗有效分辨率更细的网格；具体空间参考及面积算法由实施者依据实际影像确定，并用已知面积数据验证。
- 矩阵固定 36 个非负面积值，缺少的类别组合填零；无共同有效区域是明确失败或不可分析状态，不是成功的零矩阵。
- 矩阵总和等于共同有效区域面积，行列合计对应该区域的前后期分类面积，不要求等于整幅单期面积。

### 结果与执行流程

- 扩展现有单期识别接口，保留现有图像展示能力，增加可持久化结果标识、类别定义、平方米面积和空间统计信息。
- 新增变化任务创建、状态查询、历史列表及结果详情能力。创建输入包含前期影像标识、后期影像标识及所选识别模型标识；结果包含两期识别结果引用、有序类别、平方米矩阵、共同有效面积、统计范围、空间网格和计算时间。
- 两期使用相同模型版本。复用键应区分用户权限、影像版本、模型权重版本以及影响推理的配置；仅凭模型 ID 不能判定可复用。
- 未命中复用条件时自动执行单期识别并保存，任一期失败不得产生成功的变化结果。
- 优先扩展既有任务及分析结果存储约定，并核对迁移方式。具体表结构、端点名称和执行机制属于实现细节，不要求新增独立队列服务。
- 长时间任务须提供可查询状态，成功结果必须在文件和记录完整可读后才对外可用；失败或半成品不得命中复用。
- 历史保留计算时的影像、模型版本、统计范围和矩阵，后续资源更新不应悄悄改变旧结果。历史查询和结果复用沿用现有用户权限检查。

### 前端交互

- 六类面积展示在变化检测页面的前后两个区域；地物识别主页面不新增面积面板。两侧各自选择影像，沿用两期共用一个模型；布局细节不固定。
- 变化检测页面提供两期影像和模型选择、开始检测、执行状态、明确标注前后期的矩阵以及历史入口。
- 显示单位切换和历史查看不得触发重新推理。
- 显示首版的已配准输入要求；位置偏移不会被系统自动纠正。

## Testing Decisions

测试边界已获用户确认：以现有后端 API 为主，辅以前端会话公开行为验证；用已知分类栅格替代模型推理，保留真实空间对齐和面积计算。

- 好的测试验证用户可观察的输出、持久化后的读取及错误行为，不绑定私有函数结构或复述实现。
- 沿用现有 FastAPI TestClient、依赖覆盖和 pytest 风格，从识别及变化接口进入。用已知分类掩膜替代模型推理，保留真实网格对齐、有效区域判断、面积累计及结果序列化。
- 保存和历史读取使用隔离的测试数据库及临时结果目录验证，不能仅 mock 掉所有持久化逻辑后断言成功。
- 参考既有影像窗口读取与识别接口测试，构造小型带空间参考栅格，验证部分重叠、NoData、有效背景、坐标系与分辨率不同等情况。
- 为经纬度面积计算设置独立可信的预期值与明确数值容差，不用被测函数自身生成预期值。
- 使用已知类别组合验证全部 36 个元素、行列方向、对角线和总面积；相同分类输入应只有对角线有面积。
- 验证两期均缺失、仅一期缺失及均可复用的外部结果；替换权重或影像版本后确认输出对应新版本。
- 验证单期失败、无共同有效数据、未授权读取及保存不完整时，不出现可访问的成功变化结果。
- 前端沿用现有 Node 测试与会话依赖注入方式，覆盖选择参数、任务状态、历史加载及单位换算。
- 页面验收检查颜色对应、矩阵标题与方向、加载和失败状态以及刷新后历史可访问。模型分类精度评估不以这些确定性业务测试代替。
- 完成项目必需检查及最相关行为验证；本规格编写阶段不运行功能测试，也不宣称功能已通过测试。

## Out of Scope

- 自动影像配准和内容位置偏移纠正。
- 新模型训练、分类体系扩展或引入独立双时相变化检测模型。
- 单个地物对象的矢量提取或逐对象面积；本次统计按地物类别聚合。
- 三期以上时序分析、人工分类修订及导出报表。
- 强制引入新的任务队列、独立服务或通用工作流平台。

## Further Notes

- 本规格覆盖前后端联合功能，发布目标采用当前后端仓库，避免拆成相互缺失上下文的需求。
- 空间分类栅格必须持久化；只保存六类面积无法生成地物类型转移面积矩阵。
- 大图读取存在尺寸限制，实施时须记录真实推理分辨率，不把重采样后的结果当作源影像分辨率。
- 分析精度受到影像分辨率、模型分类误差和配准质量影响。背景类与无效数据的区分必须贯穿推理、保存、对齐及统计。
- 现有需求方案提供代码入口说明；本规格规定行为和验收，不固定具体文件路径或内部实现。


## 2026-09-08 页面与结果关联修订

- 选择影像仅按完整身份查询已有识别结果，不触发识别；分类存在但缺面积汇总时，可通过单独请求从保存栅格统计并保存面积，不重跑模型。#11 在用户发起变化检测后负责缺失分类的自动补算。
- 每侧面积标为“整幅有效区域”，矩阵为“共同有效区域”，不要求前后单期总面积等于矩阵行列合计。
- #8 拥有两侧选择状态、只读结果解析入口和唯一前端单位换算；#9 复用这些能力增加矩阵，并在执行前重新校验身份及完整性；#11 负责补算编排，#12 保留两类历史列表职责。
- 完整身份沿用 #7 的用户、影像内容版本、权重内容版本、规范化参数、分类体系版本、pipeline_version 与 grid_policy_version，不以 image_id 最新记录代替匹配。
- #9 的完整交付依赖 #8 的查询与选择状态契约；其矩阵计算核心仍只依赖 #7。不重开 #7。
