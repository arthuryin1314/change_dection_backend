# Issue #8 六类面积统计性能记录

测试日期：2026-09-08。

## 环境

- Windows 10.0.26200，AMD Ryzen 7 9700X（8 核），物理内存 50,629,509,120 bytes（约 47.2 GiB）。
- Python 3.10.20，Rasterio 1.4.4，GDAL 3.10.3，NumPy 2.2.6，pyproj 3.7.1。
- GDAL 缓存固定为 128 MiB。
- 代表性识别结果：`7713703d946e480fa11a2229c661b184`，EPSG:4528，28,311 × 26,426 像元；类别 GeoTIFF 约 22 MiB，有效掩膜约 1.1 MiB。

## 结果

| 方法 | 窗口数 | 耗时 | 峰值 RSS |
| --- | ---: | ---: | ---: |
| 原生 GeoTIFF 分块 | 11,544 | 3.789 s | 195.8 MiB |
| 256 行条带 | 111 | 6.472 s | 381 MiB |
| 64 行条带 | 443 | 6.301 s | 239 MiB |

两进程同时按原生块扫描时，各自耗时 3.92–3.97 s、峰值 RSS 195–197 MiB。正式实现因此按类别栅格的原生块迭代，不创建整图附加数组。

正式面积函数对该结果耗时 3.867 s，六类平方米结果依次为：

```text
5,551,452.076647411
42,937,297.517325506
22,106,430.080884635
41,606,227.10063764
207,015,265.87433398
159,474,309.3143193
```

有效区域总面积为 478,690,981.96414846 m²。

不同原生分块尺寸的自动化测试要求结果逐位一致；经纬度小栅格使用独立固定地表面积基准并以 `rel=1e-10, abs=1e-5 m²` 验证。

## 完整身份查询附加成本

2.26 GB 文件完整 SHA-256 为 1.16 s，10.29 GB 文件为 5.63 s；两者并发计算时分别为 1.39 s 和 6.06 s。元数据命中缓存时不重新读取文件。只读解析在缓存失效时并发计算影像与权重哈希，且不回写数据库。

## Windows 文件句柄验证

在 Rasterio/GDAL 数据集仍打开时，目录替换返回 `WinError 5`，递归删除返回 `WinError 32`。生成、面积读取和渲染因此共用跨进程结果目录锁；生成失败后的隔离目录恢复与清理由异常安全路径处理。

复现实验入口为 `scripts/benchmark_area_evidence.py`，提供 `scan`、`hash` 和 `handle-probe` 三个子命令。真实数据路径由运行者通过参数提供，不写入仓库。
