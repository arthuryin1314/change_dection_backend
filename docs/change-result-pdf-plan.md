# 变化检测 PDF 报告实现方案

日期：2026-09-19。需求已获用户最终确认；本文为实现方案，尚未修改功能代码。

## 技术选择

- 后端 Python 使用 ReportLab 生成 PDF，复用 Rasterio/Pillow 和已有分类渲染逻辑。文字与表格以真实 PDF 文本输出，图像按版面受限分辨率生成，保留完整覆盖范围。
- 前端 Vue 使用 PDF.js 预览生成文件，按需加载 worker 和预览模块；两处入口共用报告组件。无需引入覆盖 Office/CAD 等格式的 open-file-viewer。
- 使用可再分发且经过实际渲染验证的中文字体随应用提供并嵌入 PDF，附字体许可证，不依赖部署机器预装字体。
- 优先在内存中构建受限大小的四图和 PDF；不创建 PDF 数据库记录或长期文件。同步 HTTP 请求在工作线程执行渲染，不阻塞异步事件循环，不新增后台任务平台。

## 1. 参数快照

- 在 router/change_results.py 的提交输入采集点记录名称、采集日期、卫星和分辨率等业务字段。
- 从已冻结且校验内容身份的原始栅格读取源 CRS 和像素宽高，不能使用分类或变化分析网格替代源参数。
- 经 services/change_orchestration.py、services/change_inputs.py 写入现有 before_snapshot/after_snapshot JSON 的独立参数字段，兼容旧记录缺字段，预计无需增加数据库列。
- 新变化结果即使复用已有分类结果，也应保存本次输入参数快照；直接复用整个旧变化结果则保留旧结果身份与历史参数，不伪造新快照。
- 模型名称沿用快照，版本使用已有权重内容身份，并明确标作权重版本；不凭空生成版本号。
- 旧记录的未知参数显示「未记录」，不以当前数据库字段伪造检测时资料。

## 2. 报告接口与图片

建议新增 GET /api/change-results/history/{result_id}/report.pdf?unit=ha，unit 仅接受 m2/ha/km2，默认 ha。当前检测页也使用成功结果的数值 result_id 调用同一接口。

- 验证登录、结果归属和成功状态，复用历史结果读取与完整性校验。
- 从保存的 before/after 快照、class_area_m2 与 matrix_m2 取数；不接收客户端传来的报告面积或影像路径。
- 一次检查两期原图、分类栅格及有效掩膜，验证原图内容版本和分类身份，汇总缺失项并返回可展示的结构化错误。原图替换/删除或分类丢失时拒绝生成。
- 原图从已校验的源栅格按完整范围生成受限大小图片，复用实际影像的波段显示约定；分类图复用分类配色和渲染函数。两者保持对应范围和比例，不添加底图。
- 文件读取应覆盖删除/替换竞争；实现时复用现有文件锁或句柄生命周期，不能仅做一次存在性检查后无保护读取。
- 图片和矩阵的数据不足、非有限值等情况明确报错，不自动补零或重跑识别。
- 成功返回 application/pdf，设置 no-store。前端保留同一 Blob 供预览与下载。

建议模块：services/change_report.py 负责取数、身份与资源检查；utils/change_report_pdf.py 负责排版和纯数值格式化。路由仅做鉴权、参数校验与响应。

## 3. PDF 排版

- A4 纵向，中文字体嵌入，页码、报告标题和明确的生成时间。
- 信息与两期参数表；前期原图/分类图；后期原图/分类图；面积表和转移矩阵。按内容分页，不固定死页数。
- 类别名称与颜色来自现有统一分类定义；矩阵行=前期、列=后期。整张矩阵保持完整，必要时移至下一页。
- 明确单期统计整幅有效区域，矩阵统计共同有效区域；两类合计不要求相等。
- 单位与小数规则按需求执行；小于显示阈值的正面积显示带小于号的数值，真实零保留零。
- 长名称自动换行，图像等比缩放；图像降采样只影响报告展示，不影响统计值。

## 4. 前端组件和生命周期

- ChangeReportAction.vue：接收已完成 resultId，提供单位选择与「预览 PDF 报告」按钮；变化页和历史详情共同使用。
- ChangeReportPreviewDialog.vue：接收 PDF Blob 和文件名，使用 PDF.js 提供翻页/缩放，以及「导出 PDF」按钮；关闭事件向上通知。
- useChangeReport.ts：仅管理生成请求、错误、当前 Blob、取消与请求序号，避免迟到响应替换新结果。
- API 在 src/api/changeResults.ts 添加 Blob 请求；现有 request.ts 已支持 responseType=blob，报告模块单独解析 JSON 错误 Blob，保留全局登录过期行为。
- 成功生成后打开预览；点击导出创建浏览器下载。下载使用原 Blob，不重新请求服务端。
- 关闭、切换结果、组件卸载/停用时取消请求和 PDF.js 渲染并释放资源。生成中禁用重复操作，失败展示缺失项并允许重试。
- 文件名由两期名称或结果编号及生成时间组成，清理非法字符。浏览器决定保存位置。

## 5. 实施顺序与验收

1. 参数快照及新旧结果兼容，验证不改变计算身份、复用与重试行为。
2. 后端报告生成、四图版本校验与错误响应。
3. 共用预览组件、两处入口与同 Blob 下载。
4. 行为验证与 PDF 实际渲染检查。

重点验证：跨用户访问拒绝；源图删除/替换与分类文件缺失；旧结果缺参数；分类复用仍生成新快照；面积三种单位和极小值；两期范围不一致；长中文名称；生成中切换/关闭与迟到响应；预览下载字节一致；所有四图、图例和矩阵可读；资源释放。

前端运行相关行为测试、type-check、不带 --fix 的 ESLint/Oxlint 和 build；后端运行相关报告、快照、历史与变化编排回归测试。生成代表性 PDF，用 PDF 解析工具检查内容，并逐页渲染 PNG 验证中文、分页、比例和无裁切。

## 实施前需落实的技术细节

以下为实现工作项，不要求用户重复决定产品行为：核实原图波段/拉伸约定；选定可嵌入中文字体；确认工作线程并发与图片分辨率上限；确认结果身份和资源锁的准确复用位置；验证 PDF.js 与当前 Vite 集成。依据实际文件与测试落实，不在方案阶段伪称已经验证。
