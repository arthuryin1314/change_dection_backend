# ADR-0001：使用 Docker 隔离模型运行环境

## 状态

已决定

## 背景

模型库中的地物识别和变化检测模型来自不同项目，可能要求不同的 Python、PyTorch、CUDA 和第三方依赖版本。把这些模型直接导入 FastAPI 进程会造成依赖冲突，也会让上传的模型代码进入 Web 后端的权限范围。

## 决策

Web 后端只负责模型元数据、上传任务、推理任务和结果状态。模型环境由 Docker 镜像提供，模型推理由独立容器完成。管理员上传模型包后，由独立的构建 Worker 异步构建环境镜像并执行验证；Web 后端不直接调用 Docker。

镜像与模型文件分离：镜像保存运行环境，模型代码、权重和配置按内容哈希存储，推理时以只读方式挂载。每个推理任务默认启动临时容器，完成后清理。容器默认以非 root 用户运行、禁用网络，并限制 CPU、内存和 GPU。

首版使用本机文件存储，但存储接口需要保留迁移到 MinIO 或 S3 的可能。Docker 构建 Worker 只访问配置好的内部依赖源。每张 GPU 首版同时只执行一个任务，由任务队列控制并发。

## 结果

- FastAPI 环境不再需要安装所有模型的深度学习依赖。
- 模型代码、权重和环境可以分别复用和追踪，避免每次更新都重建大镜像。
- 模型上传和构建必须限制为管理员，并需要校验压缩包路径、解压大小和模型包内容。
- 模型版本的身份由环境镜像摘要、模型代码/配置哈希和权重哈希共同决定。
- GPU 调度、容器启动和构建日志需要由 Worker 负责，而不是由请求线程同步完成。

## 未决事项

- 构建 Worker 的具体队列实现和部署方式。
- GeoTIFF 图块的波段、数据类型和归一化字段的完整 `manifest.yml` 格式。
- 不同模型的指标验证阈值和测试数据来源。
