# ADR-0002：统一模型包和推理入口

## 状态

已决定

## 决策

模型库以一个压缩包作为一个模型版本的上传单位。压缩包包含 `manifest.yml`、`environment.yml`、推理源码、实际使用的权重和必要配置；不包含训练数据、无关日志、开发工具目录和不参与推理的检查点。

每个模型包必须提供统一推理入口。`manifest.yml` 声明任务类型、单时相或双时相输入、入口、类别表、资源需求、CUDA 版本、输入输出约定和版本信息。

容器内的 `rs_runner` 统一完成原始影像读取、GeoTIFF 图块切分、空间元数据传递、重叠块加权融合和结果写出。模型适配器只需要实现 `load()` 和 `predict(batch)`，返回带类别维度的概率张量；`rs_runner` 将其转换为保持 CRS 和 transform 的掩膜 GeoTIFF，并通过退出码、日志和进度信息报告执行结果。`manifest.yml` 声明 `tile_size`、`overlap`、`size_divisor`、波段和单时相/双时相输入等参数。需要特殊切片方式的模型必须通过明确的适配器声明，而不能隐式依赖宿主机目录。

模型上传后必须通过容器启动和测试推理才能进入“可用”状态；存在带标注测试数据时，再按模型声明的阈值检查 IoU 等指标。模型更新生成新版本，旧版本可以下线但不能删除仍被历史结果引用的文件。

## 结果

新增模型时，主要工作集中在整理模型包和实现入口适配器，不需要修改地物识别和变化检测页面的业务流程。前端继续通过模型编号选择模型，后端通过统一任务接口调度容器。
